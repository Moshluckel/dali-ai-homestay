# 技术架构说明

## V0 技术选择

- 前端：原生 HTML/CSS/JS（销售 Demo 最快）
- 后端：FastAPI
- 数据库：SQLite
- LLM：DeepSeek API（可选）
- 地图：高德 Web 服务 API（可选）

V0 故意不用复杂前端框架，目的是：
**最快把真实住客数据跑出来。**

验证成功后 V1 再迁移：
- Next.js / React / TypeScript
- PostgreSQL
- Redis
- 对象存储
- Sentry/日志平台
- 多租户权限

# 事实分层

## Tier 1：结构化事实
必须精确：
- Wi-Fi
- 早餐
- 停车
- 入住/退房
- 宠物
- 洗衣
- 前台联系方式

回答时禁止模型改写事实数字。

## Tier 2：平台核实的本地数据
- POI
- 体验
- 预算
- 适合人群
- 最近人工核实
- 来源

## Tier 3：生成内容
只用于：
- 组织语言
- 理解模糊需求
- 解释背景
- 个性化推荐理由

# 多租户 V1

核心约束：

每次请求都必须带 hotel_id，
后端永远在服务端解析可访问的数据范围。

禁止：
- 把全部民宿知识库一次塞给模型
- 依赖前端隐藏 hotel_id 作为权限机制
- 不同店铺共享住客原始对话

# AI安全路由

强制人工关键词：
- 退款
- 赔偿
- 投诉
- 警察
- 受伤
- 医院
- 过敏
- 丢失/被盗
- 房费争议
- 免费升级
- 免单

真实 V1 中应同时采用：
1. 关键词规则
2. 模型分类器
3. 置信度阈值
4. 敏感业务白名单
